# Outreach Agent — مساعد التواصل مع الـ HR والـ Recruiters على LinkedIn

تطبيق ويب يساعد **كل مستخدم يسجّل الدخول** على:

1. استيراد اتصالاته من ملف LinkedIn الرسمي (`Connections.csv`).
2. معرفة مَن منهم **HR أو Recruiter أو Talent Acquisition** من المسمى الوظيفي.
3. تجهيز رسالة طلب وظيفة لكل شخص بـ **اسم المستلم الأول وشركته**، و**اسم المرسل ورابط LinkedIn والبورتفوليو الخاصة به**.
4. مراجعة كل رسالة ونسخها وفتح بروفايل الشخص وتسجيل أنها أُرسلت.
5. متابعة مَن أُرسل له ومَن ردّ، ومنع التواصل مع نفس الشخص مرتين.

لكل مستخدم **حسابه وملفه الشخصي وسيرته وبياناته**، معزولة عن غيره بقواعد أمان Firestore.

> **الإرسال بإيدك دائمًا.** التطبيق لا يرسل أي رسالة على LinkedIn ولا يتصل بأي حساب. التفاصيل في [حدود LinkedIn](#حدود-linkedin-ولماذا-الإرسال-يدوي).

## حدود LinkedIn ولماذا الإرسال يدوي

حسب وثائق LinkedIn الرسمية:

- **لا يوجد API عام** لتطبيقات خارجية لقراءة الاتصالات أو إرسال رسائل أو إرفاق ملفات. هذا للشركاء المعتمدين فقط.
- واجهة **Member Data Portability** للقراءة فقط ومقصورة على الاتحاد الأوروبي وEEA وسويسرا.
- أي إرسال تلقائي آخر (كلمة المرور أو الـ cookies أو أتمتة المتصفح) **يخالف شروط LinkedIn** وقد يقيّد الحساب.

لذلك التطبيق **لا يطلب كلمة مرور LinkedIn ولا يخزن جلسات ولا يسحب صفحات ولا يتحكم في المتصفح**.

| القدرة | الحالة |
|---|---|
| استيراد الاتصالات | ✅ من ملف التصدير الرسمي |
| تحديث المسمى والشركة تلقائيًا | ❌ تعديل يدوي |
| إرسال الرسالة | ❌ يلصقها المستخدم ويرسلها بنفسه |
| إرفاق الـ CV | ❌ يدويًا بأيقونة المشبك |
| حالة التسليم | ❌ غير قابلة للتحقق. تُسجَّل "مُرسلة" بعد تأكيد المستخدم فقط |

## الحصول على Connections.csv

1. افتح <https://www.linkedin.com/mypreferences/d/download-my-data>.
2. اختر **Download larger data archive** (فيه الـ connections حسب وصف الصفحة)، أو اختر **Connections** من القائمة المخصصة إن ظهرت.
3. اضغط **Request archive**. ستصلك رسالة عند الجاهزية (حتى 24 ساعة).
4. نزّل الملف وفك الضغط وابحث عن **`Connections.csv`**.
5. ارفع **هذا الملف فقط** في **Import Connections**. لا ترفع باقي الملفات لأنها بيانات شخصية.

ملاحظات: أول الأسطر ملاحظات LinkedIn (تُتخطى تلقائيًا)، كثير من الإيميلات فارغة، والمسمى والشركة لقطة وقت التصدير وقد تكون قديمة فراجعها قبل الإرسال.

## إعداد Firebase

كل شيء على الخطة المجانية **Spark**. Firebase Storage **غير مستخدم**.

### 1) إنشاء المشروع
افتح <https://console.firebase.google.com> ← **Create a project** ← اكتب اسمًا ← أوقف Google Analytics.

### 2) Authentication
1. **Build ← Authentication ← Get started**.
2. **Sign-in method**: فعّل **Email/Password** و**Google** (اكتب اسمًا عامًا وإيميل دعم، وتجاهل تحذير SHA-1).
3. **Settings ← Authorized domains**: `localhost` ودومينات `*.web.app` و`*.firebaseapp.com` موجودة تلقائيًا. أضف الدومين المخصص لاحقًا إن استخدمت واحدًا.

### 3) Firestore
**Build ← Firestore Database ← Create database** ← اختر موقعًا قريبًا ← **Production mode**.

### 4) إعدادات الويب (قيم عامة)
**Project settings ← General ← Your apps** ← أيقونة `</>` ← سمِّ التطبيق وسجّله ← انسخ `apiKey` و`authDomain` و`projectId` و`appId`.

### 5) Hosting (مرة واحدة)
**Build ← Hosting ← Get started** وأكمل المعالج القصير (يمكنك تجاهل أوامر الـ CLI التي يعرضها فالمشروع فيه `firebase.json`).

## أين تُحفظ السيرة الذاتية

لأن التطبيق ثابت (بلا سيرفر) وبلا Storage، تُحفظ السيرة **داخل Firestore في حسابك**:

- يتحول الـ PDF إلى base64 ويُقسَّم أجزاءً في مجموعة `cvChunks` الخاصة، وبياناته في `cvDocuments`.
- قواعد Firestore تسمح **لصاحبها فقط** بالقراءة والإنشاء والحذف. لا يوجد رابط عام.
- الحد الأقصى **3 ميجا** (تفرضه القواعد). اضغط الملفات الأكبر.
- التنزيل يجمّع الملف في متصفحك.
- لكل مستخدم سيرته، ورفع سيرة جديدة يستبدل القديمة.

## النشر على Firebase Hosting

يُصدَّر التطبيق ملفات ثابتة (`out/`) ويخدمها Firebase Hosting. من فولدر المشروع:

```bash
npm install
npm run build                                   # ينشئ out/ (يقرأ .env.local)
npx firebase-tools login
npx firebase-tools use your-project-id
npx firebase-tools deploy --only hosting,firestore:rules,firestore:indexes
```

أو البناء والنشر بأمر واحد:

```bash
npm run deploy
```

يصبح الموقع على `https://your-project-id.web.app`.

ملاحظات:

- **انشر القواعد.** بدونها يظهر `Missing or insufficient permissions` في كل الصفحات. بدون terminal: الصق `firestore.rules` في **Firestore ← Rules** واضغط Publish.
- الـ index الخاص بـ `activityLogs` يظهر في **Firestore ← Indexes** بالحالة Building ثم Enabled (دقائق).
- أعد البناء والنشر عند تغيير أي `NEXT_PUBLIC_*`.
- إن قال الـ CLI إن موقع Hosting غير موجود، أكمل **Build ← Hosting ← Get started** مرة واحدة.
- **من يستطيع التسجيل؟** الصفحة عامة فيستطيع أي شخص إنشاء حساب (ولا يرى إلا بياناته). للتقييد، بعد إنشاء حساباتك عطّل **Enable create (sign-up)** من **Authentication ← Settings ← User actions** إن وُجد في الـ console عندك.

## طريقة الاستخدام

### التجهيز (مرة واحدة)
1. **Settings ← Your profile**: اكتب اسمك الكامل و**رابط LinkedIn الخاص بك** والبورتفوليو (اختياري). تُملأ بها كل رسالة.
2. **CV Management**: ارفع سيرتك (PDF حتى 3 ميجا).
3. **Message Templates**: راجع النص وعدّله ليصفك أنت (الوظيفة والخبرة). **New variant without attachment** تنشئ نسخة بلا جملة المرفق.
4. **Settings**: راجع الكلمات المفتاحية.

### الاستيراد والفرز
5. **Import Connections**: ارفع `Connections.csv` وراجع الربط والمعاينة ثم Import.
6. **HR & Recruiters**: علّم غير المناسب **Not relevant** والمؤكد **Confirmed**، وأكمل الاسم أو المسمى أو الشركة الناقصة من صفحة الجهة.

### التجهيز والإرسال
7. حدد دفعة صغيرة (5 إلى 10) واضغط **Prepare messages** (مسودات فقط، لا يُرسل شيء).
8. في **Review & Send** لكل شخص: راجع التحية والشركة ← **Copy & Open Profile** (`C`) ← في LinkedIn: Message والصق وأرفق الـ CV إن أردت وSend ← ارجع واضغط **Mark as Sent** (`M`) وعلّم التأكيد وEnter. تنتقل الصفحة للتالي.

### المتابعة
9. **Outreach History**: اضغط **Record reply** عند ردّ أحد.
10. كل فترة استورد `Connections.csv` جديدًا، فيُضاف الجدد فقط.

**عن الـ CV:** لا يمكن إرفاقه تلقائيًا. نزّله مرة واحدة بزر **Download CV** في صفحة المراجعة واختره من Downloads في كل محادثة، أو استخدم قالبًا بلا مرفق وأرسل السيرة عند ردّ الشخص.

## الاختصارات والموبايل

في **Review & Send**:

| المفتاح | الوظيفة |
|---|---|

## قالب الرسالة

القالب الافتراضي:

```text
Dear {{FirstName}},

I hope you're doing well!

I'm a Frontend Developer with 3 years of experience, specializing in Angular and React. I'm currently exploring new opportunities and would really appreciate it if you could recommend me for any suitable Frontend Developer openings at {{Company}}. I would love to be part of your team there.

I've attached my CV for your reference. You can also check out my portfolio here:
{{Portfolio}}

Thank you for your time and support!

Best regards,
{{SenderName}}
{{SenderLinkedIn}}
```

> جملة الوظيفة والخبرة مثال. **عدّلها في Message Templates** (أو غيّر `DEFAULT_TEMPLATE_BODY` في `src/lib/templates.ts`) لتصفك أنت.

| المتغير | مصدره |
|---|---|
| `{{FirstName}}` `{{LastName}}` `{{FullName}}` `{{Company}}` `{{JobTitle}}` | جهة الاتصال |
| `{{SenderName}}` `{{SenderLinkedIn}}` `{{Portfolio}}` | **Settings ← Your profile** |

قواعد الأمان:

- **اسم أول** ناقص أو غير صالح، أو **شركة** ناقصة ← الرسالة تُمنع.
- **اسمك أو رابط LinkedIn أو البورتفوليو** الناقصة (إذا استخدمها القالب) ← تُمنع مع تلميح لإكمال ملفك. بعد الإصلاح اضغط **Re-render from template**.
- الرسالة تقول "attached" بلا CV مختار ← خطأ مانع. ومع CV ← تذكير بأن الإرفاق يدوي.
- شخص سبق التواصل معه ← تحذير وتأكيد إضافي.

## الأمان

- **العزل:** كل مستخدم يقرأ ويكتب وثائقه فقط (فحوص `ownerId` في القواعد).
- **لا إرسال بدون تأكيد:** القواعد ترفض تحويل رسالة إلى "مُرسلة" بدون سجل تأكيد وتمنع تعديل نص رسالة أُرسلت.
- **سجل النشاط** للإضافة فقط.
- **الـ CV:** يُفحص النوع والحجم وبصمة `%PDF-` في المتصفح، والقواعد تحدد الحجم وعدد الأجزاء، والتخزين لصاحبه فقط بلا رابط عام.
- **الأسرار:** لا يحتاج التطبيق أسرارًا. لا ترفع مفاتيح service account أو تصديرات LinkedIn.
- **المدخلات:** تنظيف CSV (حذف رموز التحكم وتحديد الطول وحد 10 ميجا و50,000 صف).
- **الهيدرز:** `X-Frame-Options` و`nosniff` و`Referrer-Policy` في `firebase.json`.
- قواعد الأمان هي الحد الحقيقي، فإعداد Firebase للويب عام بطبيعته.

## حل المشاكل

| المشكلة | الحل |
|---|---|
| `Missing or insufficient permissions` في كل الصفحات | القواعد غير منشورة أو قديمة. أعد نشر `firestore.rules` وتأكد من اسم المشروع |
| يظهر "Demo mode" بعد النشر | `.env.local` كان ناقصًا **وقت البناء**. أصلحه وأعد البناء والنشر |
| `The query requires an index` | انشر `firestore:indexes` (أو اضغط رابط الـ console) وانتظر دقائق |
| فشل الدخول بـ Google | فعّل Google في Authentication وأضف الدومينات المخصصة في Authorized domains |
| فشل رفع الـ CV | استخدم PDF حقيقيًا أقل من 3 ميجا وتأكد من نشر القواعد وتسجيل الدخول |
| سيرة قديمة لا تُنزَّل | ارفعها من جديد |
| رسالة ممنوعة | اقرأ التحذير الأحمر (اسم/شركة ناقصة أو CV غير مختار أو ملف شخصي فارغ) ثم **Re-render from template** |
| `C` لا ينسخ | بعض المتصفحات تقيّد النسخ. استخدم **Copy Message** واستعمل HTTPS |
| صفحة بيضاء أو 404 بعد النشر | شغّل `npm run build` أولًا لينشأ `out/` ثم انشر |

## القيود المعروفة

- الفلترة والترتيب والتقسيم **في المتصفح** بعد تحميل الاتصالات: مناسب لآلاف الجهات لا مئات الآلاف.
- التصنيف يعتمد على **المسمى الوظيفي فقط** وهو غير موثّق من LinkedIn، فكل "محتمل" يحتاج مراجعة.
- المسمى والشركة لقطة وقت التصدير.
- حجم السيرة **3 ميجا** كحد أقصى لأنها تُحفظ في Firestore.
- **لم يُجرَّب مع مشروع Firebase حقيقي** في بيئة البناء: قواعد Firestore ورفع/تنزيل السيرة اختُبرا بوحدات اختبار ومراجعة فقط. بعد الإعداد ارفع سيرة ونزّلها واحفظ ملفك وجهة اتصال وشغّل `npm run test:rules`.
- بيانات Demo لا تنتقل إلى Firebase.
- لا ترسل رسائل بكميات كبيرة متتابعة. حدود LinkedIn الدقيقة غير معروفة والإرسال المكثف قد يضر الحساب.
