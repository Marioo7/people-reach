# People Reach — مساعد التواصل وبناء العلاقات المهنية

تطبيق ويب يساعدك على تنظيم جهات اتصال LinkedIn وتجهيز رسائل تواصل مهنية مخصصة للأشخاص المناسبين للوظائف أو الفرص التي تستهدفها.

يمكنك استخدامه لاستهداف **أي فئة مهنية**، مثل مسؤولي التوظيف (HR)، والـ Recruiters، وTalent Acquisition، أو أي مسميات وظيفية أخرى تضيفها بنفسك.

## روابط المشروع

- **المستودع:** https://github.com/Marioo7/people-reach
- **الموقع:** https://people-reach.web.app

> تأكد من أن الموقع المنشور يعمل قبل الاعتماد على رابط العرض المباشر.

كل مستخدم لديه حسابه وملفه الشخصي وسيرته الذاتية وجهات اتصاله وسجل تواصله الخاص. تعتمد حماية البيانات على قواعد أمان Firestore.

**مهم:** التطبيق لا يرسل رسائل LinkedIn تلقائيًا، ولا يتصل بحساب LinkedIn الخاص بك. أنت من يراجع الرسالة ويرسلها بنفسه.

## حدود LinkedIn ولماذا الإرسال يدوي

يعتمد التطبيق على ملف الاتصالات الذي تصدّره من LinkedIn، ولا يحتاج إلى تسجيل الدخول إلى حساب LinkedIn الخاص بك.

لذلك:

- لا يطلب التطبيق كلمة مرور LinkedIn.
- لا يخزن ملفات تعريف الارتباط أو جلسات تسجيل الدخول إلى LinkedIn.
- لا يسحب صفحات LinkedIn تلقائيًا.
- لا يرسل رسائل أو يرفق ملفات تلقائيًا.
- لا يستطيع التأكد من تسليم الرسالة أو قراءتها.

| العملية | طريقة التنفيذ |
|---|---|
| استيراد جهات الاتصال | من ملف `Connections.csv` الذي تصدّره من LinkedIn. |
| تحديث المسمى الوظيفي والشركة | يدويًا عند الحاجة. |
| تجهيز الرسالة | داخل People Reach. |
| إرسال الرسالة | يدويًا من خلال LinkedIn. |
| إرفاق السيرة الذاتية | يدويًا من خلال LinkedIn. |
| تسجيل حالة الإرسال | بعد أن تؤكد بنفسك أنك أرسلت الرسالة. |

راجع شروط LinkedIn وسياسات الخصوصية المعمول بها قبل استخدام التطبيق.

## التقنيات المستخدمة

- **Next.js 15** — App Router والتصدير الثابت.
- **React 19** — بناء واجهة المستخدم.
- **TypeScript** — مع تفعيل الفحص الصارم للأنواع.
- **Tailwind CSS 4** — تنسيق الواجهة.
- **Firebase Authentication** — تسجيل الدخول.
- **Cloud Firestore** — تخزين بيانات التطبيق.
- **Firebase Hosting** — نشر الموقع.
- **PapaParse** — قراءة ملفات CSV.
- **Zod** — التحقق من صحة البيانات.
- **React Hook Form** — إدارة النماذج.
- **Vitest** — الاختبارات.
- **ESLint** — فحص جودة الكود.

وفق التصميم الحالي، التطبيق يستخدم التصدير الثابت ولا يحتاج إلى سيرفر مخصص. كما أنه لا يستخدم Firebase Storage؛ تُحفظ السيرة الذاتية داخل Firestore على هيئة أجزاء.

## التشغيل السريع

### 1. تنزيل المشروع

```bash
git clone https://github.com/Marioo7/people-reach.git
cd people-reach
```

### 2. تثبيت الحزم

```bash
npm install
```

### 3. تشغيل التطبيق محليًا

```bash
npm run dev
```

افتح الرابط التالي في المتصفح:

`http://localhost:3000`

يمكنك استخدام الوضع التجريبي (Demo Mode) إذا كان مدعومًا في إعدادات المشروع. بيانات هذا الوضع محلية ولا تنتقل تلقائيًا إلى Firebase.

> لتشغيل التطبيق باستخدام Firebase الحقيقي، أكمل إعداد Firebase ومتغيرات البيئة الموضحة أدناه.

## الحصول على ملف Connections.csv

لتنزيل جهات اتصال LinkedIn:

1. افتح [إعدادات تنزيل بيانات LinkedIn](https://www.linkedin.com/mypreferences/d/download-my-data).
2. اختر تنزيل أرشيف البيانات الأكبر أو خيار الاتصالات إذا كان متاحًا.
3. اطلب تجهيز الأرشيف وانتظر حتى يصبح جاهزًا.
4. نزّل الأرشيف وفك ضغطه.
5. ابحث عن الملف `Connections.csv`.
6. ارفع الملف إلى People Reach من خلال صفحة استيراد جهات الاتصال.

**تنبيهات مهمة:**

- ارفع ملف الاتصالات المطلوب فقط، ولا ترفع ملفات أخرى تحتوي على بيانات شخصية غير ضرورية.
- قد تكون بعض عناوين البريد الإلكتروني غير متاحة.
- قد تكون المسميات الوظيفية وأسماء الشركات قديمة لأنها تعكس البيانات وقت تصدير الملف.
- راجع البيانات قبل استخدام أي رسالة للتواصل المهني.

## إعداد Firebase

يحتاج وضع Firebase الحقيقي إلى مشروع Firebase وإعدادات المصادقة وقاعدة البيانات والاستضافة.

### 1. إنشاء مشروع

1. افتح [Firebase Console](https://console.firebase.google.com).
2. أنشئ مشروعًا جديدًا.
3. أكمل إعداد المشروع وفق الخيارات المناسبة لك.

### 2. تفعيل تسجيل الدخول

من Firebase Console:

1. افتح **Build → Authentication**.
2. اضغط **Get started**.
3. افتح **Sign-in method**.
4. فعّل طرق تسجيل الدخول التي يدعمها التطبيق، مثل Email/Password وGoogle إذا كنت تستخدمهما.

### 3. إعداد Firestore

1. افتح **Build → Firestore Database**.
2. أنشئ قاعدة البيانات.
3. اختر موقع قاعدة البيانات.
4. استخدم وضع الإنتاج، ثم انشر قواعد الأمان الخاصة بالمشروع.

لا تستخدم قواعد مفتوحة تسمح لأي شخص بقراءة بيانات المستخدمين أو تعديلها.

### 4. إعداد تطبيق الويب

1. افتح إعدادات المشروع من **Project settings → General**.
2. من قسم **Your apps**، سجّل تطبيق ويب جديدًا إذا لم يكن موجودًا.
3. انسخ إعدادات Firebase المطلوبة، مثل `apiKey` و`authDomain` و`projectId` و`appId`.

هذه القيم مخصصة لتهيئة تطبيق الويب، وليست بديلًا عن قواعد أمان Firestore.

### 5. إعداد Firebase Hosting

افتح **Build → Hosting** وأكمل إعداد الاستضافة إذا لم تكن مفعّلة بالفعل.

تأكد أيضًا من أن دومين الموقع مسموح به ضمن إعدادات Authentication.

## تخزين السيرة الذاتية

وفق التصميم الحالي، لا يستخدم المشروع Firebase Storage لتخزين السيرة الذاتية.

بدلًا من ذلك:

- يتم تحويل ملف PDF إلى بيانات Base64 وتقسيمه إلى أجزاء.
- تُحفظ بيانات الملف في مجموعة `cvDocuments`.
- تُحفظ أجزاء الملف في مجموعة `cvChunks`.
- يُفترض أن تسمح قواعد Firestore لصاحب الملف فقط بالوصول إلى بياناته.
- الحد الأقصى للملف هو 3 ميجابايت وفق القيود الحالية.
- عند تنزيل السيرة، يعيد التطبيق تجميع الأجزاء داخل المتصفح.

لا يوجد رابط عام للسيرة الذاتية في التصميم الحالي.

**ملاحظة:** يجب التحقق عمليًا من إعدادات Firestore وقواعدها قبل الاعتماد على هذه الحماية في بيئة الإنتاج.

## متغيرات البيئة

أنشئ ملفًا باسم `.env.local` في المجلد الرئيسي للمشروع، بجانب `package.json`.

يمكنك استخدام `.env.example` الموجود في المستودع كنموذج.

```env
NEXT_PUBLIC_FIREBASE_API_KEY=...
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN=...
NEXT_PUBLIC_FIREBASE_PROJECT_ID=...
NEXT_PUBLIC_FIREBASE_APP_ID=...
NEXT_PUBLIC_DEMO_MODE=false
```

استبدل القيم التجريبية بالقيم الصحيحة من إعدادات مشروع Firebase.

**مهم:**

- أنشئ `.env.local` قبل تنفيذ `npm run build`.
- أعد تشغيل خادم التطوير بعد تغيير متغيرات البيئة.
- أعد البناء والنشر عند تغيير أي متغير يبدأ بـ `NEXT_PUBLIC_`.
- لا ترفع ملف `.env.local` إلى GitHub.
- لا تضع مفاتيح حسابات الخدمة أو كلمات المرور أو بيانات المستخدمين في المستودع العام.

القيم التي تبدأ بـ `NEXT_PUBLIC_` يمكن أن تظهر ضمن كود الواجهة بعد البناء؛ لذلك لا تضع فيها أسرارًا خاصة.

## النشر على Firebase Hosting

يُفترض أن يُصدّر المشروع ملفات ثابتة إلى مجلد `out/` وفق إعدادات Next.js الحالية.

من داخل مجلد المشروع، نفّذ:

```bash
npm install
npm run build
npx firebase-tools login
npx firebase-tools use YOUR_FIREBASE_PROJECT_ID
npx firebase-tools deploy --only hosting,firestore:rules,firestore:indexes
```

استبدل `YOUR_FIREBASE_PROJECT_ID` بمعرّف مشروع Firebase الحقيقي.

إذا كان سكربت `deploy` مُعدًا بالفعل في `package.json`، يمكنك استخدام:

```bash
npm run deploy
```

بعد نجاح النشر، يمكنك فتح موقعك على دومين Firebase Hosting المخصص للمشروع، مثل:

`https://people-reach.web.app`

هذا الرابط مثال على رابط الموقع المقصود؛ تأكد من أن مشروع Firebase الخاص بك مرتبط بهذا الدومين وأن النشر اكتمل بنجاح.

### ملاحظات النشر

- انشر قواعد Firestore والفهارس المطلوبة.
- إذا ظهر خطأ `Missing or insufficient permissions`، راجع تسجيل الدخول وقواعد Firestore والمشروع المحدد.
- قد تحتاج الفهارس الجديدة إلى وقت حتى تصبح جاهزة.
- إذا لم يكن Hosting مفعّلًا، أكمل إعداده من Firebase Console.
- إذا كان التسجيل متاحًا للجميع، فقد يستطيع أي شخص إنشاء حساب. راجع إعدادات التسجيل وسياسة الوصول بما يتناسب مع استخدامك.

## طريقة الاستخدام

### أولًا: إعداد ملفك الشخصي

1. افتح **Settings → Your profile**.
2. أضف اسمك ورابط LinkedIn الخاص بك.
3. أضف رابط البورتفوليو إذا كنت تريد تضمينه في رسائلك.
4. افتح **CV Management** وارفع سيرتك الذاتية بصيغة PDF.
5. راجع قوالب الرسائل وعدّلها لتناسب خبرتك والوظائف التي تستهدفها.
6. افتح إعدادات الكلمات المفتاحية وأضف المسميات التي تريد استهدافها.

### ثانيًا: استيراد جهات الاتصال

1. افتح **Import Connections**.
2. ارفع ملف `Connections.csv`.
3. راجع الأعمدة والبيانات التي اكتشفها التطبيق.
4. أكمل ربط الأعمدة عند الحاجة.
5. راجع المعاينة قبل الحفظ.
6. نفّذ الاستيراد.

### ثالثًا: تصنيف جهات الاتصال

1. افتح صفحة الجهات المستهدفة.
2. راجع المسميات الوظيفية والشركات.
3. أكد الأشخاص المناسبين أو علّم غير المناسبين.
4. أكمل البيانات الناقصة عند الحاجة.
5. عدّل الكلمات المفتاحية لتناسب أهدافك المهنية.

### رابعًا: تجهيز الرسائل

1. اختر مجموعة صغيرة من جهات الاتصال المناسبة.
2. اضغط **Prepare messages** إذا كان هذا الخيار متاحًا.
3. افتح صفحة **Review & Send**.
4. راجع الرسالة واسم المستلم والشركة.
5. انسخ الرسالة وافتح ملف الشخص على LinkedIn.
6. أرسل الرسالة بنفسك من LinkedIn، وأرفق سيرتك الذاتية يدويًا إذا أردت.

### خامسًا: تسجيل الإرسال والمتابعة

بعد أن ترسل الرسالة فعلًا:

1. ارجع إلى People Reach.
2. استخدم **Mark as Sent**.
3. أكد تسجيل الإرسال إذا طلب التطبيق ذلك.
4. سجّل الرد عند وصوله من خلال صفحة سجل التواصل.

لا تسجّل الرسالة على أنها مُرسلة إذا كنت قد نسختها فقط ولم ترسلها.

## صفحات التطبيق

قد تختلف أسماء بعض الصفحات بحسب الإصدار الحالي للتطبيق.

| الصفحة | الوظيفة |
|---|---|
| Dashboard | عرض ملخص النشاط والمسودات والجهات التي تحتاج إلى متابعة. |
| Import Connections | استيراد ملف الاتصالات ومعاينة البيانات. |
| All Contacts | البحث في جهات الاتصال وإدارتها. |
| Target Contacts | عرض جهات الاتصال المطابقة للفئات المهنية المستهدفة. |
| Contact Details | مراجعة بيانات جهة الاتصال وتعديلها. |
| Review & Send | مراجعة الرسائل ونسخها وفتح ملفات الأشخاص وتسجيل الإرسال. |
| Message Templates | تعديل قوالب الرسائل. |
| CV Management | إدارة ملف السيرة الذاتية. |
| Outreach History | متابعة الرسائل وحالات التواصل والردود. |

قد تظل بعض تسميات الواجهة ثابتة، مثل `HR & Recruiters`، حتى لو كانت الكلمات المفتاحية قابلة للتخصيص. راجع إصدار الواجهة الحالي لمعرفة الأسماء المستخدمة فعليًا.

## اختصارات لوحة المفاتيح والموبايل

إذا كانت الاختصارات التالية مدعومة في إصدار التطبيق الذي تستخدمه، فستعمل داخل صفحة مراجعة الرسائل:

| المفتاح | الوظيفة |
|---|---|
| `C` | نسخ الرسالة وفتح ملف الشخص. |
| `M` | فتح نافذة تسجيل الإرسال. |
| `S` | تخطي جهة الاتصال الحالية. |
| `←` و`→` | الانتقال إلى السابق أو التالي. |
| `Enter` | تأكيد الإجراء داخل النافذة عند استيفاء الشروط. |

قد تتوقف الاختصارات أثناء الكتابة في حقول الإدخال.

على الموبايل، استخدم الأزرار الظاهرة في الواجهة بدلًا من اختصارات لوحة المفاتيح. وقد يحتاج النسخ إلى اتصال HTTPS وصلاحيات المتصفح المناسبة.

## قالب الرسالة

يمكنك تخصيص قالب الرسالة الافتراضي وفق الوظيفة والشركة والخبرة التي تريد إبرازها.

مثال:

```text
Dear {{FirstName}},

I hope you're doing well!

I'm a Frontend Developer with 3 years of experience, specializing in Angular and React. I'm currently exploring new opportunities and would appreciate it if you could recommend me for any suitable Frontend Developer openings at {{Company}}.

I've attached my CV for your reference. You can also check out my portfolio here:
{{Portfolio}}

Thank you for your time and support!

Best regards,
{{SenderName}}
{{SenderLinkedIn}}
```

هذا مجرد مثال. عدّل الرسالة من صفحة القوالب لتناسب خبرتك وأهدافك، وتأكد من صحة كل المعلومات قبل إرسالها.

### المتغيرات المتاحة

| المتغير | مصدر البيانات |
|---|---|
| `{{FirstName}}` | الاسم الأول لجهة الاتصال. |
| `{{LastName}}` | اسم العائلة لجهة الاتصال. |
| `{{FullName}}` | الاسم الكامل لجهة الاتصال. |
| `{{Company}}` | الشركة المسجلة لجهة الاتصال. |
| `{{JobTitle}}` | المسمى الوظيفي لجهة الاتصال. |
| `{{SenderName}}` | اسمك من الملف الشخصي. |
| `{{SenderLinkedIn}}` | رابط LinkedIn الخاص بك. |
| `{{Portfolio}}` | رابط البورتفوليو الخاص بك. |

قد يمنع التطبيق تجهيز الرسالة إذا كانت بعض البيانات الأساسية ناقصة أو إذا كان القالب يشير إلى إرفاق سيرة ذاتية دون اختيارها.

تأكد من أن الرسالة النهائية مناسبة للشخص الذي تتواصل معه، وأن أي عبارة عن إرفاق السيرة الذاتية تطابق ما ستفعله فعلًا.

## الأمان والخصوصية

من المهم مراجعة النقاط التالية قبل استخدام التطبيق ببيانات حقيقية:

- **عزل بيانات المستخدمين:** يجب أن تمنع قواعد Firestore المستخدم من الوصول إلى بيانات غيره.
- **حماية السيرة الذاتية:** يجب أن تقتصر عمليات القراءة والتعديل على صاحب الملف وفق القواعد.
- **حماية بيانات الدخول:** لا ترفع كلمات المرور أو مفاتيح حسابات الخدمة إلى المستودع.
- **التحقق من المدخلات:** افحص ملفات CSV وملفات PDF قبل معالجتها.
- **تأكيد الإرسال:** لا تسجّل الرسالة على أنها أُرسلت إلا بعد تأكيد المستخدم.
- **البيانات الشخصية:** تعامل مع ملفات الاتصالات والسير الذاتية باعتبارها بيانات خاصة.
- **الاختبارات:** نفّذ الاختبارات المناسبة قبل الاعتماد على المشروع في بيئة حقيقية.

إعدادات Firebase الخاصة بالواجهة ليست بديلًا عن قواعد الأمان الصحيحة.

## حل المشكلات

| المشكلة | ما الذي يجب مراجعته؟ |
|---|---|
| `Missing or insufficient permissions` | تسجيل الدخول، وقواعد Firestore المنشورة، ومعرّف المشروع. |
| ظهور Demo Mode بعد النشر | متغيرات البيئة التي كانت متاحة وقت البناء. |
| `The query requires an index` | إنشاء الفهرس المطلوب وانتظار اكتماله. |
| فشل تسجيل الدخول باستخدام Google | تفعيل Google Authentication وإعداد الدومينات المسموح بها. |
| فشل رفع السيرة الذاتية | نوع الملف وحجمه، وتسجيل الدخول، وقواعد Firestore. |
| فشل نسخ الرسالة | صلاحيات المتصفح واستخدام HTTPS عند الحاجة. |
| ظهور صفحة فارغة أو خطأ 404 | نجاح البناء وإعداد Firebase Hosting ومسارات التصدير. |
| عدم ظهور جهة اتصال متوقعة | مراجعة ملف CSV وربط الأعمدة والكلمات المفتاحية والفلاتر. |

إذا استمرت المشكلة، راجع سجل الأخطاء في المتصفح وFirebase Console.

## القيود المعروفة

- يعتمد تصنيف جهات الاتصال على البيانات المتاحة والكلمات المفتاحية، ولذلك يحتاج إلى مراجعة بشرية.
- قد تكون المسميات الوظيفية والشركات قديمة لأنها مأخوذة من وقت تصدير ملف الاتصالات.
- لا يرسل التطبيق رسائل LinkedIn تلقائيًا ولا يستطيع التحقق من التسليم أو القراءة.
- لا يمكن إرفاق السيرة الذاتية تلقائيًا من خلال LinkedIn؛ يجب إرفاقها يدويًا.
- تخضع السيرة الذاتية لحد الحجم المحدد في الإصدار الحالي، وهو 3 ميجابايت وفق التصميم الموصوف.
- قد تتم عمليات البحث والفلترة داخل المتصفح، وهو ما قد يؤثر في الأداء مع أعداد كبيرة جدًا من جهات الاتصال.
- قد تظل بعض التسميات في الواجهة مرتبطة بـ HR & Recruiters حتى لو كانت الكلمات المفتاحية قابلة للتخصيص.
- **لا توجد حاليًا صفحة مخصصة لسياسة الخصوصية أو زر لحذف الحساب وجميع بياناته** وفق نطاق المشروع الموصوف. يجب أخذ ذلك في الاعتبار قبل إتاحته لمستخدمين آخرين.
- لا ينبغي الادعاء بأن Firebase أو عمليات رفع وتنزيل السيرة الذاتية اختُبرت فعليًا إلا بعد إجراء تلك الاختبارات على مشروع حقيقي.
- يجب مراجعة قواعد الأمان وسلوك التطبيق في بيئة الإنتاج قبل تخزين بيانات شخصية حقيقية.
